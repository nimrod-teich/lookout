# Changelog

## 0.1.3

- **Kept transcripts.** **Keep Transcript** in a card's menu keeps a copy of the session's transcript under Lookout's own storage: a hard link where the file system allows one, so no room is taken and the copy follows the file as the agent appends to it, a plain copy otherwise. The card says `kept`; **Stop Keeping Transcript** lets the copy go. Once the agent deletes the transcript, the session under Purged keeps a restore button and a **Restore Transcript** menu entry that put the copy back where the agent keeps its transcripts, the place it was kept from and nowhere else, never over a file that is there: the agent lists the session again and resumes it, though a later agent may not resume a transcript in an older format. `lookout.keepTranscripts.favourites` keeps every starred session's transcript without asking; `Lookout: Open Kept Transcripts Folder` shows the copies. And every card has the menu now, not only the running ones: an earlier, archived or purged card offers Open Conversation, Resume, Star, Archive, the notes, the keeping, and, on a purged one, Restore and Forget.
- **Tool output in the search, on request.** `lookout.search.toolOutput` (off by default) also keeps what the agents' tool calls ran and returned, Claude Code's, Codex's and Copilot's: a call's command or input and a result's text, the first and last 2 KB of each, so an error string or a command finds its session. A match reads **tool** and opens the conversation at the message the call follows. Tool output is never kept past the purge, and turning the setting off lets go of all of it at once; turning it on reads the conversations again for it, in the background.
- **The database is the search index.** With the database, the conversations are read into it and not held in memory as well, so a window no longer keeps every message twice, and the 500-session limit on what Earlier lists and the search covers is gone: every earlier session is listed and searched. An earlier session whose file has not changed since it was read is not looked at again on each search. A phrase in quotes (`"staging migrate"`) matches its words in a row, whatever the spaces or line breaks between them, with the database or without. Without the database (a VS Code whose Node has no sqlite) the search works as before, the newest 500 sessions held in memory.
- **Conversations kept past the purge.** Lookout keeps what you and the agent said in every conversation it reads, in a database of its own (`history.sqlite` under the extension's storage), written by the thread that reads the files. When the agent deletes a transcript, Claude Code after 30 days by default, the session moves to a **Purged** group under Archived: its conversation opens in the conversation tab, the search finds it, and the forget button on its card, or `Lookout: Forget Purged Conversations`, lets it go. `lookout.history.keep` (on by default) turns the keeping off: a conversation then goes when its transcript goes. The search is answered from that database through an FTS5 index: a word matches at a word's start (`retag` finds "retagging", not "pretag"), a phrase in quotes (`"retag recipe"`) its words in a row, and a new window searches at once from what every window read, with no file read again. Where the runtime has no `node:sqlite` (a VS Code from before mid-2025, or a fork on an older Electron), the search reads the files as before and nothing is kept.
- **Notes.** Notes on any session, running or not, like comments: as many as you like, each with the time it was written. A note button on every card's title row shows when you point at the card and stays lit once there are notes; a click opens the session's notes in an editor tab, as do **Add Note…** and **Show Notes** in its menu: the thread, oldest first, each note with its time and **edited** once changed, **Edit** and **Remove** on each (a removal asks for a second click), and a box for the next note, kept with **Add note** or Ctrl+Enter. On a card that is not running the newest note's first line reads under the title, in a colour of its own, with **+2** when there are more; a running card keeps its notes in its hover, so the board stays quiet. Lookout keeps the notes for the machine, one small file per noted session under its own storage with the session's title, project and branch, so every window shows them and they outlive the agent's transcript. The search reads each note as one more line of its session's conversation: a word in a note finds the session, with the notes that hold it first among its matches, marked **note**; the **Notes** chip beside **Group by** and **Sort by**, or `has:note` in the box, lists every session with notes, wherever it ran, each with its notes, and takes the other operators, the times going by when each note was written (a note names no file, so with `file:` it counts only for a session whose conversation touched one); `Lookout: Show Session Notes`, the note icon on the board's title bar, opens the search page on them.
- **Claude Code's 30-day purge.** Claude Code deletes a transcript 30 days after its last write, when it starts (`cleanupPeriodDays`, its default), and the session goes with it. `lookout.retention.days` has Lookout keep that setting at the number you choose, `3650` for ten years: it writes `cleanupPeriodDays` into Claude Code's user settings file (`~/.claude/settings.json`) when the file says otherwise, every other key kept and a copy of the file as it was beside it, and tells you what it wrote; Claude Code applies it at its next start. Managed settings, and a folder's own settings file, win over the user's, and Lookout says so instead of writing. `0`, the default, leaves Claude Code's setting alone. Lookout reads the setting the way Claude Code does (managed files and the cached server-managed settings, then each folder's local and shared files at the repository's root, then the user's).
- **Scheduled tasks on the card.** A Claude Code session that scheduled a task for itself, a wakeup after a delay or a cron job of its own, shows a clock chip with the time of the next one (`◷ in 25 min`, `◷ 09:43 tomorrow`, `+1` when more are to come); the chip's hover lists each task with its prompt, and the boat's hover carries the chip too. Lookout reads them from the transcript, the only place Claude Code records them, back to the start of the stretch it reads at a session's first sight: the chip goes when the task has run, is deleted, or the session ends, and a task scheduled by a process the session was resumed from, which died with it, does not show.

## 0.1.2

A search that is ready as soon as a window opens and never holds up VS Code, and group and sort menus that fit the board.

- **A quicker search.** Each conversation is read once and kept when its session ends or is resumed, instead of being read again whole. The lines that can hold no message and no path, most of a transcript (request records, tool output, attachments, replies that only think or run a command), are skipped without being decoded, so a long history is read in about half the time. Each message is lowercased once rather than on every search, and a search starts 100 ms after the last keystroke instead of 250 ms.
- **Search never holds up VS Code.** Lookout reads the conversations in a thread of its own, starting a few seconds after the window opens, so the first search finds them read, and VS Code's extension host, which Claude Code and every other extension in the window share, never waits on a large transcript. While some are still being read, their matches come in as each one is.
- **A new window searches at once.** Lookout keeps where each conversation's words sit in its file, never what they say, so a new window or a reload reads only those lines and what was added since: a third of a second for a history that takes four to read whole.
- **Group and sort menus that fit.** The chips say what they choose, **Group by: State** and **Sort by: Time**, and their menus open under the chip, or over it when there is more room there, never past the board's sides: one line per choice under a heading, what the choice under the pointer does at the bottom, and a scroll of their own only when the board is too short. Opening one no longer scrolls the board; the arrow keys, Home and End move through it, and Tab or Escape closes it.

## 0.1.1

Ways to organise the board, Finished across windows, and usage numbers that say why they are missing.

- **Group by.** A group chip beside the sort chip (`⊞ State`, or `Lookout: Group Sessions` from the Command Palette) makes the board's sections by project, branch, model, agent or window instead of by state: one section per value, A to Z, its heading saying what states it holds. The sessions that need you stay pinned on top under their own heading; Favourites, Parked and Earlier keep their places. Kept for every window.
- **Your order.** Pick it from the sort chip, then drag a card up or down its group to put it where you want it; it starts from the order the board showed, with new sessions first. Under any other order the cards stay put. A sort chip at the end of the search row always says the order (`⇅ Time`, `⇅ Yours`) and opens a menu to change it, as does `Lookout: Sort Sessions` from the Command Palette: time in its state (the default), latest change, name, project, tokens used or price (most first), or your order again. A grip shows beside a card's rail when you point at it. A drag among the favourites rearranges the stars. Both are kept for every window.
- **Fold any group.** A click on the heading of Favourites, Needs you, Finished, Working or Idle folds the group to its heading and count, as Earlier and Archived already did; another click opens it again. The board remembers which groups are folded, and a search opens them all while it runs.
- **Parked.** A park button on the card of a running session whose turn is over moves it to **Parked**, a folded group under Idle, out of the way until it works or waits for you again; the button on a parked card brings it back. A session idle or finished for 24 hours parks on its own (`lookout.parkAfterHours`, `0` for never) and drops its finished mark. Parked sessions have no boat in the harbour, their swatch in the legend and on the heading is idle's grey, hollow, and every window shows them.
- **A card menu in words.** Right-click a card: Jump to Session, Open Conversation, Rename, Mark as Seen, Star or Remove Star, Park or Bring Back from Parked, each shown when it applies. The park button is a parking sign, a return arrow on a parked card, centred with the check and the star beside it. Finished's "mark all seen" is a small `✓ all seen` chip right after its count. In the usage lines, the share and the time to reset have columns of their own, so the shares line up when a window has just reset, and the agents' tabs start where the limits' names do.
- **Finished in every window.** A session in another VS Code window that runs Lookout shows under Finished in this window too, as that window marks it; it used to show as Idle, since only the window that hosts a session can tell whether you looked at it. Its ✓, "mark all seen" and a jump to it clear the mark in that window as well.
- **The usage tab shows the session window.** Each agent's tab on the board shows its session window (Claude's **Session (5hr)**, Codex's **5h limit**), the limit that runs out first and the one the status bar shows, not the limit with the highest share; the tab's hover names another limit when that one is closer to its end, such as **Weekly Fable**.
- **Usage refresh waits when Anthropic asks.** When the usage endpoint answers 429, as it does when another app polls it for the same account, Lookout starts no refresh before the wait its `Retry-After` asks, in any window and `Lookout: Refresh Usage` included, and with no numbers to show the board and the status bar's hover say "Too many usage checks; next at 14:05".
- **Why there are no numbers.** A sign-in without plan limits (an API key, Bedrock or Vertex, or a long-lived token) says "No plan limits for this sign-in". A refresh that brings nothing logs why: the binary's own reason, the end of what it wrote to stderr, or that it gave no answer within 20 seconds.
- **The board never scrolls sideways.** Anything wider than the board is cut at its edge, and the board can no longer be scrolled to the side.

## 0.1.0

First release.

- **Board.** A view in the activity bar. At the top, the harbour: a night scene with the lighthouse, its sweeping beam, and the sessions as boats on the water, placed by state and by time in that state; the beam lights the boats it passes and swings to a boat before a jump, and the tide rises with the 5-hour usage. Below, one card per session, grouped into Needs you, Finished, Working and Idle, showing its tool calls per minute over the last 15 minutes (fewer while it is younger than that, so the bars grow from the left), how full its context window is, the tokens it has used with their price at API list rates, its project and git branch (in a worktree, that worktree's), where it runs, and its model with the reasoning effort of its last reply (`Opus 5.5 · high`). Click a boat or a card to jump; rename a session from its card through the agent's own rename; hide a state group with a click on the legend. A tab or terminal with nothing sent is left off the board while it is idle; once it works it is listed as "Empty tab" (or "Empty session" in a terminal) until the agent titles it. A session in its first minute counts as idle.
- **Why a session needs you.** A waiting session says what kind of wait it is and quotes the ask: a permission with the tool and its command or file (`Bash: npm test`), a question with its answers, a plan to approve, or another dialog with the agent's own word for it. The cards, the jump list and the notification all show it. A session of this window whose last reply asks you something is counted as needing you too, after the prompts, on a dashed card marked "asked you a question", until it works again or you dismiss it with the card's ✓ (`lookout.state.typedQuestions`, on by default); it is announced once, like a prompt, when you were not looking.
- **Where a state comes from.** A card's hover says whether its state comes from the session file, the transcript or the process, and how old that is. A session file that records no state, or cannot be read, leaves the session "State unknown". A working session whose transcript has been silent for more than 10 minutes reads "Working, quiet 12m": its card stops moving.
- **Background jobs.** A Claude Code session whose turn is over while shell commands it started in the background still run stays under Working, saying "1 background job · 2h" and how long they were busy ("busy 45m"); after 15 minutes with no CPU and no output it says "idle 20m: may be stuck", and "orphaned" when Claude Code no longer follows a job. When the last one ends the session is Finished. Linux and WSL.
- **Context pressure.** A card's context ring turns amber from 75% and red from 90%, and a pin on its pulse marks the minute the agent compacted the conversation.
- **Earlier sessions.** Under the live sessions, a collapsed group holds the sessions that are not running and that the agent has not archived: those of this window's folders, or of every project on the machine, as a toggle on its heading says (kept per workspace); the newest 500 are listed, 20 to a page with Newer and Older under them, with a note when there are more. A click on a session of this window's folders resumes it in the agent's panel; a session of another project opens its conversation rather than an empty tab, since the agent resumes it only in a window open on its folder.
- **Archive.** An archive button on each earlier card moves the session to an Archived group under Earlier, paged like it and kept for every window; the button there brings it back, and a session that runs again leaves the archive. Lookout keeps the archive itself and writes nothing to the agents.
- **Search.** A search box above the cards looks through every conversation, live and earlier, in the Earlier group's scope: what you wrote and what the agent replied. Every word must appear in one message. Operators narrow it: `since:` and `before:` (`today`, `yesterday`, `12h`, `3d`, `2w`, `2026-10-01`), `project:`, `branch:`, and `file:` for the paths the agent's tool calls worked on; operators alone list the sessions they keep. Sessions with matches stay on the board, each with its newest three matches under the card and the words marked; the rest hide until the box is cleared.
- **A search page.** Every conversation's matches in an editor tab, with the room to read them: `Lookout: Search All Sessions`, the search icon on the board's title bar, or a click on the board's match count. Sessions with matches are listed newest match first, each headed by its title, whether it is running or earlier and its match count, then its project, branch and the days it spans with how long ago it last moved (`Oct 16 → Oct 18 · active 3h ago`), and up to 20 matches each; the page takes the board's operators.
- **The conversation tab.** A click on a match, or on "+N more", opens the session's whole conversation in a tab, scrolled to the match, under its title, project, branch, message count and the same span; the tab wears the harbour's night colours and renders the messages' Markdown; it has its own search with next and previous, dims what does not match, follows the conversation as it grows, and has a button to bring the session's own tab or terminal forward.
- **Favourites.** A small star on every card stars the session; starred sessions are gathered at the top of the board, running or not and whatever project they belong to, and a click jumps to them, resumes them, or opens their conversation. Stars are kept for the machine, so every window shows them.
- **Tabs restored after a reload.** The agent restores its tabs after a window reload but starts a session only once its tab is opened; until then the board keeps the session, idle, on a card that says "Tab open · not started", and a click opens the tab.
- **Status bar.** The usage and nothing else: the 5-hour window as a ten-cell bar coloured by consumption, green, amber from half, red from 80%, with the time to its reset, `32% · 1h12m` (`lookout.statusBar.usageReset`, on by default), and a red background when a limit is nearly used up. The hover lists every agent's limits with a bar in its colour; a click opens the board.
- **Jump.** `Lookout: Jump to Session` (`Ctrl+Alt+J`) lists the sessions, the ones that need attention first, with how long each has been in its state, and brings the chosen one's tab or terminal to the front; a panel session's tab comes forward at its newest message, with the cursor in its prompt box, or at the prompt it waits on, through Claude Code's own "Focus last message" and "Focus input". `Lookout: Jump to Next Session That Needs You` (`Ctrl+Alt+Shift+J`) goes straight to the one that has waited longest and cycles through the rest on repeated presses. A session hosted by another VS Code window on the same machine jumps through that window: it brings the session's tab or terminal forward and comes to the front; when the desktop does not let it, Lookout says which window to switch to. Sessions in other windows' terminals are named after their window.
- **Finished turns.** A session that finishes a turn while you are not looking at it is marked finished until you open its tab or terminal; the marks survive a window reload. For a terminal session, looking means you were last in its terminal: you brought it forward or sent its session a prompt, and went to no tab, editor or panel session since, since VS Code keeps a terminal its active one while you work elsewhere. `Lookout: Mark All Sessions as Seen` clears them.
- **Notifications.** A notification with a Jump button when a session starts to wait for you (`lookout.notifications.waiting`, on by default) or finishes a turn (`lookout.notifications.done`, off by default). While VS Code is not the window in front, the same shows on the desktop: notify-send on Linux, Notification Center on macOS, a Windows toast on Windows and from WSL (`lookout.notifications.os`, on by default), with a short sound if you want one (`lookout.notifications.sound`). It cannot jump, so it names the key that does. At most one per session and event every 30 seconds (`lookout.notifications.cooldownSeconds`); while three or more sessions need you, one sums them up. SSH and container remotes have no desktop to reach and skip it.
- **Usage.** The board and the status bar's hover list every limit as Claude Code's own panel names it, **Session (5hr)**, **Weekly (7 day)** and the per-model weekly ones such as **Weekly Fable**, each with its share used and "Resets in 3h". Lookout says once per window when the 5-hour window reaches 70% and 90% and the week 90% (`lookout.usage.alerts`, on by default). Numbers more than 30 minutes old, or from before a reset, turn grey. Claude Code fetches the numbers again when they are older than 10 minutes (`lookout.usage.refresh`: `auto`, `manual` or `off`), with its own credentials and the config directory Lookout reads, at most once every 3 minutes on the machine and less often after fetches that bring nothing new; not while `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` is set for Claude Code. `Lookout: Refresh Usage` fetches at once. Numbers cached for another account, or a cache that does not parse, show "No usage reported".
- **Agents.** Claude Code in its VS Code panel and in terminals; Codex in its extension's panel, VS Code's Chat and terminals; Copilot in VS Code's Chat and in terminals (each has its own entry below). Each agent has a switch of its own in the **Agents** section of Lookout's settings (`lookout.agents.claude`, `lookout.agents.codex`, `lookout.agents.copilot`), which takes effect at once; with every agent off, the board says so and links to them. Lookout reads what each agent already writes on disk: it installs no hooks, writes no agent's configuration, reads no credentials and calls no service. Sessions in another VS Code window are listed with that window's name. A session Lookout cannot bring forward, outside VS Code or in an agent's panel in a window where Lookout does not run, says so, and a click opens its conversation. Each agent has its own colour and boat, Claude a coral sloop; once the board shows two or more agents (running, earlier or in the usage), the boats in the harbour, a thin edge and a small boat on every card, a chip per agent in the legend that hides that agent's sessions, usage and search matches, the jump list, the status bar's hover, the usage groups, the search page and the conversation tab tell them apart, with the agent's name in hovers and lists (`lookout.agentMarkers`: `auto`, `always`, `never`). Usage takes a few lines on the board: a tab per agent naming the limit it is closest to running out of, and the chosen agent's limits below, one line each; the status bar's bar is the window under the most pressure (`lookout.statusBar.usageAgent` pins one). An action an agent does not allow (jump, rename, resume) is left off its sessions rather than offered and failing; the README's Supported agents table lists what each allows.
- **Codex.** Threads in the Codex extension's panel (its side bar and editor tabs), sessions of VS Code's Chat (its **Codex** type), sessions of the `codex` program in VS Code's terminals and in terminals elsewhere on the machine, and `codex exec` runs: working, idle, or needing you, with Codex's command approvals as permissions quoting the command and its questions with their options, in the same groups as Claude's. Each card has Codex's own name for the thread, its folder, git branch, model, context and pulse, and the hover says the state is read from the tail of Codex's rollout, since Codex keeps no state file. A click on a terminal's session brings its terminal to the front; a click on a thread of the extension opens it in the extension's editor, and one of VS Code's Chat in an editor of the Chat, its approval prompt included in both. `lookout.agents.codex` turns it off; `lookout.codexHome` points at another home than `CODEX_HOME` or `~/.codex`. Codex's earlier threads are under Earlier with Claude's, in the same scopes, searched with the same operators (`file:` goes by the files Codex changed and read) and read in the conversation tab; a click on one of this window's folders runs `codex resume` in a new terminal there. Compressed rollouts are not read, and the Earlier group says how many. Codex's **5h limit** and **Weekly limit** come in a usage group of their own, from what Codex records with each reply, with the same colours, grey when stale and the same alerts, named for Codex; the status bar's bar can follow them (`lookout.statusBar.usageAgent`). A Codex card shows the thread's tokens, priced at OpenAI's API list rates where the model has a listed price, marked as API-equivalent.
- **Copilot.** Every Copilot session of VS Code's Chat (the **Copilot**, **Copilot CLI** and **Local** types), and sessions of the `copilot` program in terminals, tied to their process by the lock Copilot keeps in each session's folder: working or idle as Copilot's own flag says, needing you while an approval it asked for (a command or a file to write) is open, quoting the command or the file. Cards show Copilot's title for the session, its folder, git branch, model, effort, context and tokens. A click on a session of VS Code's Chat opens it in an editor, with the approval it waits on; one in a terminal brings the terminal forward. Earlier Copilot sessions are listed, searched and read like the others, and resume in VS Code's Chat or with `copilot --resume` in a new terminal. `lookout.agents.copilot` turns it off; `lookout.copilotHome` points at another home than `COPILOT_HOME` or `~/.copilot`.
- **Icon.** The lighthouse is the mark everywhere: the activity bar, and the status bar item through an icon font the extension ships.
- **Platforms.** Linux, macOS, Windows, WSL, and SSH and container remotes.
