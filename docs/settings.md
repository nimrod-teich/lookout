# Settings

Every `lookout.*` setting, with its default. The settings come in two sections, **Agents** (a switch per agent, and where each keeps its files) and **General**. The commands and their keys are in the [README](../README.md#commands).

| Setting | Default | Description |
| --- | --- | --- |
| `lookout.statusBar.enabled` | `true` | Show Lookout's item in the status bar: the usage, and a click to open the board. |
| `lookout.statusBar.showUsage` | `true` | Show the 5-hour usage as a coloured bar in the status bar item, the weekly usage on an account without a 5-hour limit (a verified Ultra account); the hover lists every limit. |
| `lookout.statusBar.usageReset` | `true` | After the usage bar, the time until the 5-hour window resets: `32% · 1h12m`. |
| `lookout.usage.refresh` | `auto` | `auto`: fetch when the numbers are older than 10 minutes or a window has reset; at most once every 3 minutes on the machine, and after a fetch that brought no new numbers the wait doubles each time, up to 30 minutes. When Anthropic's usage endpoint answers 429, no fetch starts before the wait its `Retry-After` asks, as Claude Code reads it (5 minutes without one, an hour at most), in either mode. `manual`: fetch only on `Lookout: Refresh Usage`. `off`: never start the Claude Code binary; show only what it cached. While `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` is set for Claude Code, Lookout does not fetch either. |
| `lookout.usage.alerts` | `true` | Say when the 5-hour window reaches 70% and 90% and a weekly limit 90%, the all-models one or a model's own such as Fable's: once per window, in the VS Code window in front (any window when none is) and, while VS Code is not in front, on the desktop. |
| `lookout.notifications.waiting` | `true` | Notify when a session of this window starts to wait for you and you are not looking at it. |
| `lookout.notifications.done` | `false` | Notify when a session of this window finishes a turn and you are not looking at it. |
| `lookout.notifications.os` | `true` | While VS Code is not in front, also show those notifications on the desktop. |
| `lookout.notifications.sound` | `false` | Play a short system sound with each desktop notification. |
| `lookout.notifications.cooldownSeconds` | `30` | A session gets at most one desktop notification per event in this time. While three or more sessions need you, one notification sums them up. |
| `lookout.state.typedQuestions` | `true` | Count an idle session as needing you when its last reply asks you something. Off: such sessions are Finished or Idle like any other. |
| `lookout.answers.enabled` | `true` | Answer a Claude Code session's prompt from its card while it runs in a terminal of this window: **Yes** or **No** to a permission when the card shows all the call would do (a whole command, address or file to read; not a file to write or edit), or one of a single question's options. Lookout types the answer's key into the terminal only while the session still shows that prompt. Off: the cards show what the session asks, and a click jumps to it. |
| `lookout.parkAfterHours` | `24` | A running session idle or finished this many hours goes under **Parked**, folded at the bottom of the board, and comes back when it works again. `0`: only the sessions you park yourself. |
| `lookout.history.keep` | `true` | Keep what you and the agent said in every conversation Lookout reads, in a database of its own, after the agent deletes the transcript: the session stays under **Purged**, readable and searched, until you forget it. Off: nothing shows under **Purged**, a conversation purged from then on goes at the sweep after the next, in case its transcript was only out of reach for a moment, and what was kept before stays until forgotten. Needs a VS Code whose Node has `node:sqlite`. |
| `lookout.search.toolOutput` | `false` | Also keep what the agents' tool calls ran and returned (commands, their output, errors) in the search, so an error string or a command finds its session; a match reads **tool**, and a click opens the conversation at the message the call follows. Each call and each result is kept to its first and last 2 KB. Off by default: tool output is where secrets end up (environment dumps, tokens, file contents), and it is several times the size of the conversation. Never kept past the purge: when the agent deletes a transcript, its tool output goes, though its conversation stays. Turning it off lets go of every tool call and result kept at once. Needs the database. |
| `lookout.keepTranscripts.favourites` | `false` | Keep a copy of every starred session's transcript under Lookout's own storage, as if **Keep Transcript** were chosen for each from its card's menu. A kept transcript of a purged session can be put back for the agent to resume. |
| `lookout.retention.days` | `0` | Keep Claude Code's transcripts this many days: Lookout writes `cleanupPeriodDays` into Claude Code's user settings file (`~/.claude/settings.json`) when it says otherwise, every other key kept and a copy of the file as it was beside it; Claude Code applies it at its next start. `0` leaves Claude Code's own setting (30 days by default); `3650` is ten years. Managed settings, and a folder's own `.claude/settings.json`, win over it; Lookout says so when it writes. |
| `lookout.worktrees.folders` | `[]` | Folders that hold your git repositories: **Clean Up Worktrees** looks in each, and up to two levels below it, for repositories, and checks every worktree each one lists, wherever the worktree lives. Empty: the folders that hold the repositories your sessions ran in. The repositories your sessions ran in are always checked. |
| `lookout.worktrees.rebuildable` | `node_modules`, `.terraform`, build output and caches | Ignored files and folders a tool builds again, by name (`node_modules`, `.terraform`) or by extension (`*.pyc`): a worktree whose only ignored files are these loses nothing when it goes. Any other ignored file, an `.env` or a kubeconfig, holds the worktree for review, named on its row, since `git worktree remove` deletes ignored files without asking. The default: `node_modules`, `dist`, `out`, `build`, `.next`, `next-env.d.ts`, `.nuxt`, `.svelte-kit`, `.turbo`, `.parcel-cache`, `.vite`, `.cache`, `coverage`, `.nyc_output`, `target`, `.gradle`, `.terraform`, `.terraform.lock.hcl`, `.venv`, `venv`, `__pycache__`, `.pytest_cache`, `.mypy_cache`, `.ruff_cache`, `.tox`, `*.pyc`, `*.tsbuildinfo`, `*.vsix`, `.DS_Store`. |
| `git.path` (VS Code's own) | none | The git **Clean Up Worktrees** runs: a path, or a list of which the first that exists counts, as VS Code's git reads it. None that exists: `git` from the PATH. The page needs git 2.17 or newer and says so when it finds none or an older one. |
| `lookout.statusBar.usageAgent` | `auto` | Whose usage the status bar's bar shows when more than one agent, or account, reports usage: `auto`, the window under the most pressure (the highest share used, fresh numbers first); `claude`, `codex` or `copilot`, that agent's (of Claude's accounts, the one under the most pressure); or `claude:` and an account's label from `lookout.claudeConfigDirs`, such as `claude:personal`, that account's. A pin that reports none leaves the bar to `auto`. |
| `lookout.agentMarkers` | `auto` | When to tell agents apart by colour and boat: `auto` once the board shows two or more agents (running, earlier or in the usage), `always`, or `never`. |
| `lookout.agents.claude` | `true` | Watch Claude Code: its panel and `claude` in terminals, with its usage. Off: none of its sessions, earlier sessions, search matches or usage, none of its files read, and Claude Code never run to refresh the usage. |
| `lookout.agents.codex` | `true` | Watch Codex: the Codex extension's panel, VS Code's Chat, `codex` in terminals and `codex exec` runs. |
| `lookout.agents.copilot` | `true` | Watch Copilot: VS Code's Chat (its Copilot, Copilot CLI and Local sessions) and `copilot` in terminals. |
| `lookout.claudeConfigDir` | `""` | Claude Code config directory to read sessions from. Empty uses `CLAUDE_CONFIG_DIR` from the Claude Code extension's settings or the environment, then `~/.claude`. |
| `lookout.claudeConfigDirs` | `[]` | More Claude Code config directories, one per account, for each account you run with its own `CLAUDE_CONFIG_DIR`. Lookout finds most by itself (`lookout.claudeDiscoverDirs`); list one here to name it, or to watch one no process runs now outside your home directory. An entry is a path, or `label=path` to name it (`personal=~/.claude-personal`); unnamed, a directory goes by its name less a leading `.claude-`, and `~/.claude` by `default`. Write each path as you give it to `CLAUDE_CONFIG_DIR`: Claude Code names a directory's stored sign-in after that exact spelling, a trailing slash included. Their sessions show on the board with the others, and each account's usage in a tab of its own, refreshed on its own sign-in; with two or more directories, every Claude Code card carries its directory's label. The Claude Code panel runs the first directory, so an earlier session of another resumes in a terminal, `claude --resume` with that directory in `CLAUDE_CONFIG_DIR` and no `CLAUDE_CODE_OAUTH_TOKEN` or `ANTHROPIC_API_KEY`, so its own sign-in applies. |
| `lookout.claudeDiscoverDirs` | `true` | Find the Claude Code config directories of your other accounts by themselves, and watch them as if `lookout.claudeConfigDirs` listed them: `~/.claude` and the home directory's `.claude-<name>` folders, and each directory a running process of yours was given in `CLAUDE_CONFIG_DIR`, read from the processes' environments on Linux and macOS. Only a directory with Claude Code's config file, `.claude.json`, counts. Lookout looks every minute, and a directory once found stays watched while it holds that file. Off: only the directories you list. |
| `lookout.claudeAccountNames` | `{}` | Names for Claude accounts, by their e-mail address, as in `{ "you@work.example": "work", "you@home.example": "personal" }`. A named account's name goes on the cards of the sessions that ran on it, read from the organization Claude Code stamps into each transcript when a session starts or resumes, and on its usage while it is signed in. It is for accounts you switch between in one config directory, with `/login` or a tool that swaps sign-ins, and it replaces a directory's label from `#lookout.claudeConfigDirs#`. Lookout learns an account's organization when a watched directory is signed in to it, and keeps only a hash of the address. Sessions started before Claude Code stamped transcripts, around version 2.1.280, carry no name. |
| `lookout.codexHome` | `""` | Codex's home folder, where its `sessions` are. Empty uses `CODEX_HOME`, then `~/.codex`. |
| `lookout.copilotHome` | `""` | Copilot CLI's home folder, where its `session-state` is. Empty uses `COPILOT_HOME`, then `~/.copilot`. |
